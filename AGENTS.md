# Project Instructions

This repository contains a new competition website project intended for
NOIT and other information technology competitions.

## Mandatory sources

Before performing any project work:

1. Read `docs/NOIT_MASTER_PROMPT.md` completely.
2. Read and analyze `docs/NOIT_REGULATIONS_2025_2026.pdf`.
3. Treat the master prompt and the applicable competition requirements as mandatory.
4. Clearly flag any rule that may belong only to the 2025–2026 competition year
   and may require verification for a later competition year.

## Workflow

1. Do not start implementation before the problem, concept, MVP,
   user flows, architecture, database model and testing strategy are approved.
2. Work in small, verifiable stages.
3. Keep the project runnable after every major stage.
4. Run relevant tests after every significant change.
5. Never claim that a feature works unless it has been implemented and verified.
6. Never invent survey results, statistics, user feedback or test results.
7. Clearly mark mocks, prototypes and unfinished functionality.
8. Do not change the approved core idea without explicit permission.

## Security

1. Never place real passwords, API keys or database credentials in source code.
2. Never commit `.env`, `.env.local` or secret files.
3. Add placeholders only to `.env.example`.
4. All AI API calls requiring secret keys must run through the backend.
5. Validate inputs on the server.
6. Apply authorization and least-privilege database access.
7. Stop and request approval before any destructive database operation.

## Quality

1. Use TypeScript when appropriate.
2. Keep business logic separate from visual components.
3. Add error handling, loading states and empty states.
4. Implement responsive design and accessibility.
5. Maintain documentation, setup instructions and a license register.
6. Prefer a smaller completed product over many unfinished features.
7. Avoid unnecessary dependencies and infrastructure.
8. Keep the application working after every major change.
